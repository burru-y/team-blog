# 10 月 25 日：把站点改了一版，然后搬上服务器

今天基本都泡在这个项目上。上午改界面，下午部署，晚上处理迁移和一堆积压的小问题。

## 上午：界面整体换掉

之前的界面是「卡片堆叠」，看着像模板。原因是每块内容都套一个带边框的卡片，页面全是同样的方块。

今天的做法是**先定排版规则，再改页面**：

- 一级标题统一 `text-3xl` 到 `text-4xl`，之前从 `text-2xl` 到 `text-5xl` 有五种
- 列表类内容用分隔线代替卡片边框
- 卡片只留给真正的独立单元（成员、成果、打卡）

然后引入了 `motion`，接了几个社区组件：

| 组件 | 用在哪 | 效果 |
|---|---|---|
| 倾斜卡 | 成员/成果卡片 | 鼠标移上去会朝光标方向微倾 |
| 侧栏 | 全站导航 | 桌面可折叠成图标栏，手机变抽屉 |
| 时间线 | 版本页 | 可横向拖拽 |
| 上传队列 | 发布页 | 拖拽上传 + 进度条 |

导航从顶部搬到左侧是个不小的改动。原来顶栏一排链接：成果、时间线、写笔记、发布、留言、后台、头像。搬到侧栏后按用途分组：浏览 / 发布 / 管理，权限不同的用户看到不同分组。

## 中午：几个细节反复调

**打卡卡片**改了四版才对：

```
第 1 版  卡片缩在左半边，右边空一大块
第 2 版  补了边框，但和左边热力图不等高
第 3 版  等高之后，热力图挤在顶部，下面一片空白
第 4 版  内容垂直居中，终于对了
```

问题出在 `display: flex` 和网格拉伸的关系上——给外层加了 `flex` 之后，内层卡片从「块级自动铺满」变成「按内容收缩」，宽度就只占左半边了。

**热力图的月份标签**竖着排成了一列。查了半天发现：标签容器宽度等于一个格子（11px），「11月」放不下，浏览器在数字和「月」之间换行，十二个月就叠成了一竖。加了 `whitespace-nowrap` 并去掉「月」字才正常。

这类问题代码逻辑完全正确，不看实际渲染发现不了。

## 下午：部署到阿里云

买了台 2 核 2G 的机器，Ubuntu 24.04，杭州。6 个容器：数据库、后端、前端、AI 服务、nginx、备份。

部署过程中最花时间的不是写配置，是**等下载**。

### 构建慢的原因

第一次构建 20 分钟没跑完，我以为是机器不行。后来把每一步耗时打出来：

```
apk add tzdata curl          285 秒   ← Alpine 官方源
mvn dependency:go-offline    380 秒   ← Maven Central
拉 maven 镜像 145MB          251 秒   ← 3M 带宽已跑满
编译代码                      几十秒
```

**编译只占几十秒，90% 时间在等网络。** 换成阿里云镜像源后：

```
apk     285 秒 → 9 秒
Maven   380 秒 → 200 秒
```

### 数据迁移踩的坑

把本地数据库导出来传到服务器恢复，结果刷了 15 行红字：

```
ERROR: role "ai_reader" does not exist
```

一开始以为数据坏了。看清楚才发现报错全是 `GRANT` 语句——**数据本身没问题，是缺一个只读角色**。

这个角色在本地是数据库初始化时自动建的，但生产的 compose 我没挂那个初始化脚本，所以新库没有它。

修法是只挂角色脚本，不挂测试库脚本：

```yaml
- ../init/01-roles.sql:/docker-entrypoint-initdb.d/01-roles.sql:ro
```

全部迁移成功。备份也验证了一遍：手动跑一次 `pg_dump`，再建个临时库把 dump 恢复进去数行数，确认这份备份真能用。

**存了备份不等于备份可用**，这一步以前我都是跳过的。
