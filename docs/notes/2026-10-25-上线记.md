## 二、踩的坑

### 坑 1：Docker 构建全部 ECONNRESET

不是网络坏了，是 **Docker 被配成走 `127.0.0.1:7897` 的代理，而代理软件没开**。请求全部打到空气上。

改成「系统代理」后，容器直连恢复正常。

### 坑 2：构建慢到想放弃

第一次构建 20 分钟没完成。看时间分布发现编译只占几十秒，剩下全是下载：

```
apk add tzdata curl     285 秒   官方源
mvn dependency:offline  380 秒   Maven Central
```

换成阿里云镜像源后：

```
apk     285 秒 → 9 秒
Maven   380 秒 → 200 秒（依赖数量没变，只是每个快了）
```

### 坑 3：`pg_restore` 报 15 个错

恢复备份时满屏 `role "ai_reader" does not exist`。

原因：生产 compose 没挂载初始化 SQL，新库没有这个只读角色。数据本身没问题，报错全是 `GRANT` 语句。

修法：compose 里挂单个文件，**只挂角色脚本，不挂测试库脚本**。

```yaml
- ../init/01-roles.sql:/docker-entrypoint-initdb.d/01-roles.sql:ro
```

### 坑 4：两处样式 bug

**双边框**：给卡片套了一层倾斜组件，倾斜组件和内层 `Card` 各有一个边框，叠在一起发虚。

**月份竖排**：热力图的月份标签容器只有 11px 宽，「11月」放不下就换行，十二个月叠成一竖。

两个都是「没看组件内部结构就往上套」导致的。

### 坑 5：GitHub 连不上

服务器 `git clone` 两次失败（TLS 中断、443 超时）。最后改用本地打包 + Xftp 上传。

本地推送也有几次失败，提交在本地保留，不影响部署。

## 三、值得记住的几条

**① 慢的时候先看时间分布，别猜**

构建慢不是「电脑不行」，是 90% 时间在等网络。把每一阶段耗时打印出来，问题一眼就看见。

**② 备份要验证能恢复**

存了 dump 不等于有备份。今天专门建了个临时库，把 dump 恢复进去数行数，确认能用。

**③ 生产库和开发库的差异要显式补齐**

开发环境靠初始化脚本建的角色，生产没挂这个脚本就没有。这类「只在开发环境存在的东西」最容易漏。

**④ 中断构建会浪费已下载的层**

`Ctrl+C` 一次，之前下载几分钟的镜像层可能白费。开始构建前把该做的事做完。
