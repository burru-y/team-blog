# 欲晓：一个团队技术博客的设计与技术选型

## 为什么做这个

班级里有几个技术方向不同的同学：有人写后端、有人做前端、有人刚入门在学 Python。大家的成果散在微信群、个人博客、GitHub 里，过一学期就谁也找不到了。

想做一个地方：

- 把项目和奖项集中放，能点进去看详情
- 学习笔记能沉淀下来，不是发完就沉底
- 有个轻量的机制鼓励持续输出（打卡 + 积分）
- 访客能直接就某个项目提问，不用等人回答

最后一条是它和普通博客最大的区别。

## 技术栈

| 层 | 选型 | 为什么 |
|---|---|---|
| 后端 | Spring Boot 4 + Java 17 | 主流、生态全、类型安全 |
| 前端 | Next.js 15 App Router | 服务端渲染，首屏快；路由即文件 |
| AI 服务 | FastAPI + Python | 调用模型生态最好，SSE 写起来简单 |
| 数据库 | PostgreSQL 16 | 有 JSON 字段、有窗口函数、免费 |
| 部署 | Docker Compose | 单机够用，六个容器一条命令起 |

选 Next.js 而不是纯 React，是因为列表页、个人页都要读数据库。放在服务端渲染，访客拿到的就是完整 HTML，不用等 JS 加载完再发请求。

## 三个值得说的设计

### 1. 分页用游标，不用页码

普通分页是 `?page=2&size=20`，靠 `OFFSET` 跳过前面的数据。问题在于：**翻页过程中有人插入了新内容，第二页会漏掉或重复。**

我们用游标：

```
GET /api/v1/projects?limit=20&cursor=MjAyNi0xMC0yNVQxMjozNDo1Nnw0ZjNh
                                        ↑ 上一页最后一条的时间 + ID
```

游标是 base64 编码的 `时间戳|UUID`，查询条件是 `WHERE (created_at, id) < (?, ?)`。这样无论中间插入多少条，下一页都紧接着上一页，不会跳也不会重复。

### 2. 令牌撤销靠版本号

JWT 是无状态的，签发后服务端不记录。好处是不用查库，坏处是**改密码、被踢下线之后，旧令牌在过期前依然有效**。

解法是在用户表加一个 `token_version` 字段，签发时写进 JWT：

```json
{ "sub": "用户ID", "role": "MEMBER", "tv": 7 }
```

每次验签多查一次库，比对 `tv` 和数据库里的值。改密码时把 `tv` 加一，**所有旧令牌立刻失效**。

代价是每次请求多一次数据库查询——这个代价可以接受，因为比起「密码泄露后 7 天内令牌还能用」，多一次查询太便宜了。

### 3. AI 服务不信任前端

AI 功能按身份分两档：

| | 访客 | 成员 |
|---|---|---|
| 每天次数 | 8 次（按 IP） | 不限 |
| 单次长度 | 300 字 | 800 字 |
| 能问什么 | 只能问本项目内容 | 可以问通用问题 |

问题在于：**前端可以伪造身份**。所以 AI 服务自己验 JWT 签名，不信前端传来的 `role` 参数。

摘要接口更严格，用 HMAC 签名：Java 用共享密钥算出签名，Python 验证。这样即使有人直接访问 AI 服务的端口，没有密钥也调不动。

## 前端几个具体问题

### 上传进度必须用 XHR

`fetch` 没有上传进度事件——只有下载侧能读流。想让进度条真的动，得用 `XMLHttpRequest`：

```js
request.upload.addEventListener("progress", (event) => {
  const percent = Math.round((event.loaded / event.total) * 100);
});
```

不然用户看到的就是「转圈 → 突然完成」，5MB 的图会以为卡死了。

### 悬停效果要判断设备

卡片跟随鼠标倾斜很好看，但**触屏设备上会出问题**：手指点下去时浏览器会补发 `mouseenter`，卡片莫名其妙转一下。

所以先问一句：

```js
window.matchMedia("(hover: hover) and (pointer: fine)")
```

不满足就完全关闭这个效果，也不绑事件。

### 月份标签会竖排

热力图的月份标签，容器宽度等于一个格子（11px）。「11月」三个字放不下，浏览器就在数字和「月」之间换行，十二个月叠成一竖。

修法是 `whitespace-nowrap` + 标签只留数字。**这类问题不看实际渲染是发现不了的**，代码逻辑完全正确，就是显示错。

## 数据库迁移

用 Flyway，SQL 文件按版本号排列：

```
V1__init.sql          建表
V2__display_name.sql  加显示名字段
V3__invite_revoke.sql 邀请链接加撤销
```

应用启动时自动检查并执行未跑过的迁移，跑过的记在 `flyway_schema_history` 表里。

好处是**换机器时不用手工建表**，代码拉到哪、数据库就跟到哪。

## 测试策略

后端有 231 个测试，其中两个是「结构型」的：

**权限矩阵测试**：扫描所有注册的接口，对照一份权限清单，检查每条路径的角色要求是否符合预期。**新增接口时如果忘了登记，测试直接失败。**

**匿名访问测试**：逐个请求公开接口，确认不用登录能拿到数据；再请求需要登录的接口，确认返回 401。

这类测试的价值不在「测出 bug」，而在于**防止后来的人悄悄改坏规则**。

## 学到的几件事

**① 类型不能代替校验**

前端把数据标成 `string`，不代表运行时真的是字符串。后端每个入口都要校验，前端只负责提示。

**② 无状态是有代价的**

JWT 省了查库，但撤销、踢人、改权限都要额外设计。**没有免费的方案，只有把代价放在哪的选择。**

**③ 慢的时候先量一量**

构建慢，直觉是「机器不行」。打印出每步耗时才发现，编译只占几十秒，剩下全是下载依赖。换镜像源后从 20 分钟降到 5 分钟。

**④ 边界情况写在注释里**

比如「游标分页为什么不用页码」「令牌版本号为什么每次要查库」。**这些理由不写下来，三个月后自己都会想改成"更简单"的写法**，然后重新踩一遍坑。
