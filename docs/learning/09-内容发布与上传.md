## 0. 先讲人话

前面所有接口都是"读"：看成员、看成果。这一批第一次出现**写**：

```
有人发布 → 有人能看见 → 有人能把它下架
```

写接口比读接口危险得多，因为**用户可以往里塞东西**：

- 塞别人的 id（想改别人的成果）
- 塞不合规的内容（项目没有正文）
- 塞一个改名成 .png 的可执行文件
- 塞一段 `<script>`

这一批就是把这些口子一个个堵上。

## 1. 先理解问题

### 1.1 越权：URL 规则管不到"这是不是你的"

现在有两层校验：

```
第一层：登录了吗？        → Security 过滤链（URL 规则）
第二层：是管理员吗？      → URL 规则 + hasRole
第三层：这条是你的吗？    → ❌ URL 规则表达不了
```

第三层必须**读数据**才能判断，所以只能写在 Service 里：

```java
if (actorRole != Role.ADMIN && !project.isOwnedBy(actorId)) {
    throw new BusinessException(FORBIDDEN, "只能修改自己发布的成果");
}
```

这就是 S-01 说的"三重校验"。少一层，成员 A 就能改成员 B 的成果。

### 1.2 按类型校验：一条规则，两种形状

成果分三种，必填字段不一样：

| 类型 | 必填 |
|---|---|
| `PROJECT` | 仓库链接 + 正文 |
| `CERTIFICATE` / `AWARD` | 图片 **或** 链接（二选一） |

数据库里其实有 CHECK 约束兜底，但它报的是：

```
new row for relation "projects" violates check constraint "ck_projects_required"
```

用户看不懂。所以应用层先拦，返回 **422 `RULE_VIOLATED`** + 人话——注意是 422 不是 400：
格式没错，是**语义**不满足。

### 1.3 每日计分上限：内容照收，分不照给

规则（需求 v1.0 §2.4）：每篇 +10 分，**每天最多 3 篇**。

第 4 篇会发生什么：

```
内容 → 入库（正常保存）
积分 → 不加（point_events 里没有这一条）
```

为什么要限制：不限制的话，一个人一天复制粘贴 100 篇就 1000 分了。

为什么是"篇数"不是"字数"：字数可以刷，篇数至少要有一次真实的提交动作，而且边界清楚、容易测。

### 1.4 上传：类型看内容，不看声明

把 `virus.exe` 改名成 `cat.png` 是**零成本**的。扩展名和 `Content-Type` 都只是客户端的说法：

```
文件名：cat.png          ← 客户端可以随便写
Content-Type: image/png  ← 客户端可以随便写
文件头：MZ...            ← 这才是事实
```

所以要读 **magic bytes**（文件头）：

| 类型 | 开头字节 |
|---|---|
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| JPEG | `FF D8 FF` |
| GIF | `47 49 46 38`（"GIF8"） |
| WebP | `52 49 46 46` + 第 8 字节起是 "WEBP" |

### 1.5 为什么禁 SVG

SVG 是 XML，可以内嵌脚本：

```xml
<svg xmlns="http://www.w3.org/2000/svg">
  <script>alert(document.cookie)</script>
</svg>
```

浏览器会**把它当图片渲染，但脚本照样执行**。这是存储型 XSS 的经典载体：
攻击者上传一次，所有访问这个页面的用户都会中招。

它的开头是 `<svg` / `<?xml`，匹配不上任何图片签名。所以"只认白名单签名"这一条
同时解决了它——不需要额外写 `if (svg) reject`。

## 3. 代码逐行

### 3.1 归属校验

```java
private void requireOwnerOrAdmin(Project project, UUID actorId, Role actorRole) {
    if (actorRole == Role.ADMIN) {
        return;                                   // 管理员直接放行
    }
    if (!project.isOwnedBy(actorId)) {
        throw new BusinessException(ErrorCode.FORBIDDEN, "只能修改自己发布的成果");
    }
}
```

**为什么管理员先返回**：管理员不需要是作者。顺序反过来写（先判作者）会让管理员被误拦。

**为什么错误信息是 403 不是 404**：这条资源确实存在，只是你不能改。如果用 404 假装不存在，
用户会以为是链接错了——而且前端也没法区分"没有"和"没权限"。

### 3.2 按类型校验

```java
switch (type) {
    case PROJECT -> {
        if (isBlank(githubUrl)) throw new BusinessException(RULE_VIOLATED, "项目类成果必须填仓库链接");
        if (isBlank(contentMd)) throw new BusinessException(RULE_VIOLATED, "项目类成果必须填正文");
    }
    case CERTIFICATE, AWARD -> {
        if (isBlank(githubUrl) && isBlank(imageUrl)) {
            throw new BusinessException(RULE_VIOLATED, "证书/奖项至少要有一张图或一个链接");
        }
    }
}
```

`switch` 用枚举而不是字符串：**新增类型时编译器会提醒你**（没有 default 分支时），
用字符串就会悄悄漏掉。

### 3.3 每日计分上限

```java
LocalDate today = LocalDate.now(clock);

// 先数"今天之前已发了几篇"，再插入——插入之后再数会把本次算进去
long alreadyToday = learningLogRepository.countByUserIdAndLogDate(userId, today);

LearningLog log = LearningLog.create(...);
learningLogRepository.save(log);

boolean counted = false;
if (alreadyToday < DAILY_SCORING_LIMIT) {
    counted = pointService.award(userId, PointEventKind.LEARNING_LOG,
            log.getId().toString(), LEARNING_LOG_POINTS);
}
```

三个要点：

**① 用业务日期 `log_date`，不用 `created_at`。** 两者都要：前者用于"今天写了几篇"，
后者用于排序与审计。用 `created_at` 判断会在 23:59 与 00:01 之间产生跨天争议。

**② 顺序是"先数再插"。** 反过来会把本次算进"已发篇数"，导致第 3 篇就被拦。

**③ 用 `Clock` 而不是 `LocalDate.now()`。** 测试里能注入固定时间，否则这段逻辑
只有在特定日期才可测。

### 3.4 积分：账本 + 原子更新

```java
pointEventRepository.saveAndFlush(PointEvent.of(userId, kind, refId, points));
userRepository.addPoints(userId, points);
```

```java
@Modifying
@Query("update User u set u.totalPoints = u.totalPoints + :points where u.id = :id")
int addPoints(@Param("id") UUID id, @Param("points") int points);
```

**为什么不用"查出来 +10 再 save"**：并发下两个请求读到同一个旧值，后写的覆盖先写的，
分就丢了。一条 SQL 由数据库保证原子性。

**"只加一次"靠什么**：`point_events` 上的唯一约束 `(user_id, kind, ref_id)`。
代码里的 `existsBy...` 只是省一次注定失败的插入，不是保证。

### 3.5 文件头校验

```java
static String detectImageMime(byte[] bytes) {
    if (startsWith(bytes, 0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A)) return "image/png";
    if (startsWith(bytes, 0xFF, 0xD8, 0xFF)) return "image/jpeg";
    if (startsWith(bytes, 0x47, 0x49, 0x46, 0x38)) return "image/gif";
    if (startsWith(bytes, 0x52, 0x49, 0x46, 0x46) && /* 第 8 字节是 WEBP */) return "image/webp";
    return null;   // 不认识 → 拒绝（SVG 也在这里被挡住）
}
```

**落盘文件名用服务端生成的 UUID**：

```java
String fileName = UuidUtils.v7() + "." + extFromMime;
```

不用客户端文件名，是为了防两件事：路径穿越（`../../etc/passwd`）和相互覆盖
（两个人都传 `avatar.png`）。

**扩展名来自检测结果，不是客户端给的那个**：客户端说 `.jpg`、内容是 PNG，就存成 `.png`。

### 3.6 代码文件 → Markdown 代码块

```java
String fence = text.contains("```") ? "````" : "```";
String markdown = fence + language + "\n" + text.stripTrailing() + "\n" + fence;
```

**为什么要判断围栏长度**：如果文件内容里本身有 ` ``` `（比如贴了一段 Markdown），
用三个反引号会把代码块提前截断，后面的内容就跑到外面去了。用四个就没问题。

### 3.7 Markdown 渲染：安全性来自"不做什么"

```tsx
<ReactMarkdown remarkPlugins={[remarkGfm]} components={{...}}>
```

**关键是没装 `rehype-raw`。** react-markdown 默认不解析 HTML，正文里的 `<script>`
会被转义成 `&lt;script&gt;`，**根本进不了 DOM**。

如果哪天为了"支持在 Markdown 里写 HTML"而加上 `rehype-raw`，就必须同时接
`rehype-sanitize`。这两件事必须成对出现——单加 `rehype-raw` 等于主动开一个存储型 XSS。

链接统一加属性：

```tsx
<a target="_blank" rel="noopener noreferrer">
```

- `noopener`：新页面拿不到 `window.opener`，无法反向控制本站
- `noreferrer`：不泄漏来源地址

`javascript:` 这类协议由 react-markdown 的默认 `urlTransform` 过滤（会被清成空串）。

## 4. 一次发布的完整时间线

```
T0  成员打开 /publish，填写标题、描述、链接、正文
T1  选配图 → POST /api/v1/uploads/images（multipart）
    → 后端读文件头 → 不是图片就 400；是图片就存成 UUID.xxx → 返回 /uploads/xxx.png
T2  点发布 → POST /api/v1/projects（JSON + Bearer token）
    → 安全链：登录了吗 → 通过
    → Service：类型必填校验 → 通过
    → 入库 → 201 + 详情
T3  前端跳转 /projects/{id}
T4  访客打开 /projects → 服务端组件拉列表（只含 ACTIVE）
T5  管理员点"下架" → DELETE /projects/{id}
    → Service：管理员放行 → status=REMOVED, removed_at=now()
T6  访客再打开 /projects/{id} → 404（列表里也没有了）
T7  数据库里那一行还在，只是 status 变了
```

## 5. 六个容易写错的细节

### 5.1 只做 URL 级权限

成员 A 改成员 B 的成果会成功。必须读数据判断归属。

### 5.2 用 `created_at` 判断"今天"

23:59 发的和 00:01 发的会被算成同一天或不同天，取决于时区与时间点。要用业务日期。

### 5.3 计分先插后数

插入之后再 `count`，会把本次算进去，导致第 3 篇就开始不加分。

### 5.4 信任扩展名

`cat.png` 里可能是 exe、是脚本、是 SVG。必须读文件头。

### 5.5 用 `dangerouslySetInnerHTML` 渲染 Markdown

那等于把用户输入直接塞进 DOM。react-markdown 走的是"解析成 React 元素"的路径，
天然不执行 HTML。

### 5.6 加上 `rehype-raw` 却忘了 `rehype-sanitize`

前者打开 HTML 解析，后者负责清洗。只加前者 = 存储型 XSS。

## 6. 反面教材

| 写法 | 后果 |
|---|---|
| 只在 Controller 判断"是不是作者" | 别的入口（定时任务、批量脚本）漏掉 |
| 归属判断写成 404 | 用户以为链接坏了，前端无法提示"没权限" |
| 用 `String` 比较类型 | 新增类型时静默漏掉分支 |
| 先插库再数篇数 | 计分上限少一篇 |
| 用 `LocalDate.now()` 硬编码 | 测试不可控，跨时区行为诡异 |
| 信任 `Content-Type` | 改个请求头就绕过 |
| 客户端文件名直接落盘 | 路径穿越、覆盖别人的文件 |
| Markdown 用 `dangerouslySetInnerHTML` | 存储型 XSS |
| 错误信息里回显 SQL/堆栈 | 信息泄漏（S-09） |

## 7. 怎么验证（Gate G3 的实测）

后端 **99 个测试**，其中这一批新增：

| 用例 | 验证 |
|---|---|
| 项目缺链接 → 422 | 按类型校验 |
| 证书只有图片 → 201 | 二选一规则 |
| 成员改他人成果 → 403 | 归属校验 |
| 管理员改他人成果 → 200 | 管理员放行 |
| 下架后详情 404、列表不含、库里仍是 REMOVED | 软下架 |
| 当天前 3 篇各 +10，第 4 篇不加分 | 计分上限 |
| 改后缀的 exe 被拒 | magic bytes |
| SVG 被拒 | XSS 载体 |
| `.py` → ` ```python ` 块 | 代码转 Markdown |

前端与端到端（**真起前后端**）：

| 步骤 | 结果 |
|---|---|
| 成员发成果 | 201 |
| 成员发学习内容 | 201，计分 true |
| 访客看成果流/详情/学习内容 | 全部 200 且含标题 |
| 管理员下架 | 200 |
| 下架后详情 | **404**，成果流里消失 |
| 数据库 | `status=REMOVED`，行仍在 |

XSS 实测（往正文塞攻击载荷再 curl 页面）：

| 载荷 | 结果 |
|---|---|
| `<script>alert('xss')</script>` | 转义，无真实 script 标签 |
| `<img src=x onerror=alert(1)>` | 转义 |
| `[x](javascript:alert(1))` | `href=""`（`href="javascript:` 出现 0 次） |
| 正常外链 | `rel="noopener noreferrer"` |

## 9. 自测题

1. 为什么"这条是不是你的"不能写在 URL 权限规则里？
2. 归属校验失败为什么返回 403 而不是 404？
3. 按类型校验为什么用 422 而不是 400？
4. 每日计分上限为什么要"先数再插"？
5. 为什么用 `log_date` 而不是 `created_at` 判断"今天"？
6. 为什么总分要用 `UPDATE ... SET total_points = total_points + ?`？
7. 为什么禁 SVG？"只认文件头白名单"为什么能顺带解决它？
8. Markdown 渲染的安全性来自哪个"没做"的决定？

<details>
<summary>答案</summary>

1. URL 规则只能匹配"路径 + 方法 + 角色"，表达不了"这条数据属于谁"，那需要查库。
2. 资源确实存在，只是不能改。404 会让用户以为链接错了，前端也无法区分"没有"和"没权限"。
3. 400 是格式错（JSON 写坏了、字段类型不对）；422 是格式对但语义不满足（项目缺正文）。
4. 插入之后再 count 会把本次算进去，导致第 3 篇就被判定超限。
5. `created_at` 是时间戳，跨时区/跨零点会争议；`log_date` 是业务自然日，规则清晰可测。
6. 并发下"读-改-写"会丢更新（两个请求读到同一个旧值），一条 SQL 由数据库保证原子性。
7. SVG 是 XML，可内嵌 `<script>`，浏览器会渲染它并执行脚本，是存储型 XSS 载体。它的开头是 `<svg`/`<?xml`，匹配不上任何图片签名，所以白名单天然挡住它。
8. 不装 `rehype-raw`。默认不解析 HTML，`<script>` 只会变成转义文本。

</details>

## 10. 术语

| 名词 | 一句话 |
|---|---|
| 归属校验 | 判断"这条数据是不是你的"，必须读数据 |
| 软下架 | 不删数据，只改状态，前台按不存在处理 |
| magic bytes | 文件开头的固定字节，用来识别真实类型 |
| 存储型 XSS | 攻击载荷存进数据库，所有访客都会中招 |
| 原子更新 | 一条 SQL 完成"读+写"，并发不丢更新 |
| 账本 | 只追加的事件流水，可对账、可去重 |
| 业务日期 | 按自然日算的日期，与时间戳区分 |
| 幂等 | 同一操作重复执行，结果与执行一次相同 |
