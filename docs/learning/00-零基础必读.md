# 零基础必读：读代码前需要知道的九个概念

本文汇总项目中反复出现的基础概念。每节给出定义、在代码中的具体位置，以及常见误解。

不必通读。遇到看不懂的代码时，回查对应小节通常够用。

---

## 1. HTTP 报文

一次请求和一次响应都是纯文本，结构固定。

请求：

```
POST /api/v1/auth/login HTTP/1.1
Host: localhost:8443
Content-Type: application/json

{"username":"admin1","password":"..."}
```

依次是请求行（方法、路径、协议版本）、头部、空行、正文。

响应：

```
HTTP/1.1 200 OK
Content-Type: application/json
Set-Cookie: rt=...; Path=/api/v1/auth; Secure; HttpOnly; SameSite=Lax

{"ok":true,"data":{"accessToken":"..."}}
```

### 1.1 方法

| 方法 | 语义 | 本项目用途 |
|---|---|---|
| GET | 读取，不产生副作用 | 列表、详情 |
| POST | 创建，或触发动作 | 登录、发布、打卡、AI 提问 |
| PATCH | 局部更新 | 改资料、改角色 |
| DELETE | 删除 | 下架内容、删除评论 |

约定不等同于强制。GET 也能改数据，代价是缓存、重试和爬虫会产生意外副作用。

### 1.2 参数位置

| 形式 | 示例 | 服务端取法 |
|---|---|---|
| 路径变量 | `/projects/{id}` | `@PathVariable` |
| 查询参数 | `?limit=20&cursor=abc` | `@RequestParam` |
| 请求体 | `{"title":"..."}` | `@RequestBody` |

本项目分页用查询参数，资源标识用路径变量，写入内容放请求体。筛选条件不进请求体，因为 GET 请求带正文时不同客户端行为不一致。

### 1.3 状态码

| 码 | 含义 | 本项目触发条件 |
|---|---|---|
| 200 | 成功 | 查询、更新 |
| 201 | 已创建 | 发布内容、注册 |
| 204 | 成功无正文 | 删除 |
| 400 | 参数不合法 | 校验失败、请求体格式错误 |
| 401 | 未认证 | 未带 token、token 过期、密码错误 |
| 403 | 已认证但无权限 | 成员访问管理端、删除他人内容 |
| 404 | 资源不存在 | 路径错误、内容已下架 |
| 409 | 状态冲突 | 重复打卡、邮箱已注册 |
| 410 | 资源已失效 | 邀请码过期或已使用 |
| 422 | 语义错误 | 评论层级超限 |
| 429 | 请求过频 | 登录失败过多、AI 额度用尽 |
| 500 | 服务端异常 | 未预期错误 |

401 与 403 的分工：401 表示身份不成立，403 表示身份成立但权限不足。混用会让客户端无法判断是否该跳转登录页。

### 1.4 常用头部

| 头部 | 作用 |
|---|---|
| `Content-Type` | 正文格式，本项目固定 `application/json` |
| `Authorization` | 携带 Bearer token |
| `Set-Cookie` | 服务端下发 Cookie |
| `Cache-Control` | 缓存策略，动态数据用 `no-store` |

## 2. Cookie

Cookie 是浏览器保存、并在后续请求中自动附带的小段文本。HTTP 本身无状态，Cookie 是跨请求识别同一浏览器的机制之一。

### 2.1 四个属性

| 属性 | 作用 | 本项目取值 |
|---|---|---|
| `HttpOnly` | 禁止 JavaScript 读取 | 开启，防 XSS 窃取 |
| `Secure` | 仅 HTTPS 下发送 | HTTPS 部署时开启 |
| `SameSite` | 限制跨站携带 | `Lax`，防 CSRF |
| `Path` | 限定发送路径 | `/api/v1/auth`，刷新令牌只发给刷新接口 |

`Path` 常被忽略。刷新令牌限定到认证路径后，其他接口的请求不携带它，泄露面随之减小。

### 2.2 本项目的用法

access token 存放在内存（JavaScript 变量），不写 Cookie，也不写 localStorage；refresh token 放 `HttpOnly` Cookie。

页面被注入脚本时，攻击者读不到 refresh token。access token 有效期 30 分钟，过期后由 refresh 换取。

## 3. JSON 与统一响应结构

所有接口返回同一结构：

```json
{"ok": true, "data": {}}
```

```json
{"ok": false, "error": {"code": "VALIDATION_FAILED", "message": "标题不能为空"}}
```

`code` 供前端判断分支，`message` 供人阅读。前端按 `code` 映射提示文案，不直接展示服务端 `message`。

分页响应：

```json
{"ok": true, "data": {"items": [], "nextCursor": "MjAyNi0xMC0yNHw..."}}
```

游标分页不使用页码和总数，原因见笔记 08。

## 4. 编码、加密、哈希

三个词经常混用，用途完全不同。

| 概念 | 是否可逆 | 是否需要密钥 | 项目中的用途 |
|---|---|---|---|
| Base64 | 可逆 | 无 | 游标编码、Basic 认证头 |
| 加密 | 可逆 | 有 | 未使用 |
| 哈希 | 不可逆 | 无 | 密码、邀请码、IP 存储 |
| HMAC | 不可逆 | 有 | 内部接口签名 |

### 4.1 Base64 不是加密

Base64 只把二进制转成可打印字符，任何人可解码，不能用于保护数据。

本项目用它对游标编码，因为游标含 UUID 与带时区的时间戳，直接放进 URL 需要转义。

### 4.2 两种哈希

| 用途 | 要求 | 本项目算法 |
|---|---|---|
| 存密码 | 慢，抗暴力破解 | BCrypt，成本因子 12 |
| 存邀请码、IP | 快，抗碰撞 | SHA-256 |

密码必须用慢哈希。SHA-256 每秒可计算上亿次，不适合存密码。

### 4.3 加盐

同一密码，不同用户存储的哈希值必须不同。做法是给每个用户生成随机盐，与密码一起哈希。

BCrypt 内部处理盐，调用方无需管理。这是选择它而非手工 SHA-256 的原因之一。

## 5. 有状态与无状态

### 5.1 Session 方案

服务端保存会话数据，浏览器持有会话 ID。优点是服务端可随时让会话失效；缺点是请求必须回到保存会话的那台机器，多实例需要共享存储。

### 5.2 JWT 方案

服务端不保存会话，把身份信息签进令牌，每次请求带上。任意实例都能校验；缺点是令牌签发后无法单方面收回，只能等过期。

### 5.3 本项目的做法

access token 用 JWT，有效期 30 分钟，令牌内含 `tokenVersion`，每次请求与数据库中的值比对。改密码或改角色时该值加一，旧令牌立即失效。

这样校验无需查会话表，同时保留主动失效能力，代价是每个请求一次数据库查询。

## 6. 并发

### 6.1 线程池

Web 服务器用固定数量的线程处理请求。请求进来时取一个线程，处理完归还。线程数有限，单次请求耗时越长，可同时服务的请求越少。

这一点直接决定了 AI 服务的部署方式，见笔记 12。

### 6.2 共享可变状态

多个线程读写同一变量时需要同步。本项目用 `ConcurrentHashMap` 存登录失败计数与 AI 额度，它是线程安全的哈希表。

普通 `HashMap` 在并发写入时可能损坏内部结构，表现为数据丢失或死循环。

### 6.3 内存计数的局限

内存计数在进程重启后清零，多实例之间不共享。本项目的限流与额度因此是够用但不精确的取舍，单实例部署下可接受。

## 7. 时间

### 7.1 三种表示

| 类型 | 含义 | 用途 |
|---|---|---|
| `Instant` | 时间轴上的点，UTC | 数据库存储、令牌签发 |
| `OffsetDateTime` | 带偏移的时间点 | 与 `Instant` 互转 |
| `LocalDate` | 日历日期，无时区 | 打卡日期、统计 |

### 7.2 打卡的日期归属

打卡以服务器时区的日期为准。项目在 `application.yml` 固定时区，避免容器时区不同导致同一天被算成两天。

跨时区用户会看到日期与本地不一致。这是有意选择：积分规则需要全局一致的日界线。

## 8. 数据存放位置

| 位置 | 特点 | 本项目用于 |
|---|---|---|
| 内存 | 最快，进程结束即丢失 | 限流计数、AI 额度 |
| 数据库 | 持久，可查询，有事务 | 业务数据 |
| 浏览器 | localStorage、内存、Cookie | access token 放内存，refresh 放 Cookie |

判断依据是三项：数据丢失是否可接受、是否需要跨实例共享、是否敏感。

## 9. 术语表

| 术语 | 解释 |
|---|---|
| DTO | 数据传输对象，用于接口出入参，与实体分开 |
| 实体 | 与数据库表对应的 Java 类 |
| 仓储 | 数据访问接口，Spring Data 自动实现 |
| 迁移 | 版本化的建表与改表脚本 |
| 幂等 | 同一操作执行多次与执行一次结果相同 |
| 软删除 | 只标记删除时间，不物理删除 |
| 游标分页 | 用上一页最后一条的位置继续查询 |
| 限流 | 限制单位时间内的请求次数 |
| 熔断 | 达到阈值后停止调用，避免持续消耗 |
| SSE | 服务器向客户端单向推送文本流 |
| HMAC | 用共享密钥对消息计算摘要，用于验证来源 |
