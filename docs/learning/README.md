## 写法标准（04 起执行）

面向"只学过 JavaWeb"的读者，每篇必须包含：

```
0. 先讲人话：这一节解决什么问题（一个具体场景，不带术语）
1. 先理解敌人/问题：不这么写会发生什么
2. 设计：把问题拆成 2~3 个必须回答的小问题
3. 代码逐行：贴完整方法，逐段解释"为什么这么写"
4. 完整时间线：一次请求从进来到返回，带耗时数字
5. 容易写错的细节：每条都给"如果写错会怎样"
6. 反面教材表：五种错误写法 + 后果
7. 测试怎么写：连测试代码一起讲，说明为什么这样测
8. 动手练习：不看代码，按步骤自己实现一遍
9. 自测题 + 答案（折叠）
10. 本节术语表
```

**00-必读**提供前置知识，各篇按编号引用（如"见 00-§4"）。

## 目录结构：为什么不是 `controller/ service/ mapper/`

如果你先学的苍穹外卖/黑马那套，会觉得本项目"没分层"。其实层次都在，只是分组轴不同：

- **按层**（`controller/`、`service/`、`mapper/`）：找"所有 Controller"很方便，但改一个功能要横跨四个目录，文件数会在一层里线性堆积。
- **按业务**（`user/`、`auth/`、`project/`）：一个功能的所有代码在同一个包，新增功能不修改既有目录。

三处看起来"少了一层"，是技术栈差异，不是风格差异：

| 苍穹外卖有 | 本项目 | 原因 |
|---|---|---|
| `mapper/` + XML | `user/UserRepository` | 用 Spring Data JPA，接口即 DAO，无 XML |
| `service/` + `service/impl/` | 直接一个 `UserService` 类 | 单实现不抽接口（J-26） |
| `sky-pojo` 独立 Maven 模块 | 实体与 DTO 放在业务包 | 单模块；真需要拆分时再拆 |

完整的对照表和分层职责见 [`teamblog/api/README.md`](../../teamblog/api/README.md)。
