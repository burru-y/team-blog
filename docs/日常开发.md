# 以后怎么改网站

## 一句话版本

```powershell
# 本地改代码 → 一条命令部署
cd D:\TeamBlog\teamblog\ops
.\deploy.ps1 -Service web
```

改前端用 `web`，改后端用 `api`，改 AI 用 `ai`，不确定就 `.\deploy.ps1 -All`（慢，逐个构建）。

实测：无改动 14 秒，有改动 1–3 分钟。

---

## 日常开发的三种场景

### 场景 1：只改样式、文案、页面结构（最常见）

```powershell
# 1. 本地热更新预览
cd D:\TeamBlog\teamblog\web
pnpm dev                    # 打开 http://localhost:3000

# 2. 改完确认无误，部署
cd D:\TeamBlog\teamblog\ops
.\deploy.ps1 -Service web
```

**注意**：本地 `pnpm dev` 连的是本地数据库。要连服务器数据库看真实数据，需要配 `API_ORIGIN`，不建议——本地数据够用了。

### 场景 2：改后端接口

```powershell
cd D:\TeamBlog\teamblog\ops\compose
docker compose up -d db     # 只起数据库，供本地跑后端
cd ..\..\api
.\mvnw.cmd spring-boot:run  # 本地起后端，改代码自动重启

# 验证后部署
cd ..\ops
.\deploy.ps1 -Service api
```

### 场景 3：改数据库结构

**不能直接改表**，要走 Flyway 迁移，否则服务器上的库和你本地的不一致。

流程：

1. 在 `teamblog/api/src/main/resources/db/migration/` 新建文件，按版本号命名：

```
V1__init.sql
V2__add_display_name.sql
V3__add_invite_revoke.sql
V4__add_project_tags.sql      ← 你的新迁移
```

2. 文件内容只写增量变更：

```sql
ALTER TABLE projects ADD COLUMN tags text;
```

3. 本地跑一遍确认没问题
4. 部署：`.\deploy.ps1 -Service api`

应用启动时会自动执行未跑过的迁移，跑过的记录在 `flyway_schema_history` 表里。

**迁移文件一旦部署过就不能改**——改了不会重新执行，会导致本地和服务器不一致。要改就加 V5。

## 部署脚本做了什么

```
1. 把 teamblog/ 和 docs/ 打成 zip（排除 node_modules、.next、target、.git）
2. scp 传到服务器 /root
3. 服务器上解压覆盖
4. 只重建指定的服务
5. 重启该服务
6. 健康检查：首页 200 + /api/v1/health 返回 UP
```

`.env.prod` 不在压缩包里，所以密钥、AI key 不会被覆盖。

## 常用参数

```powershell
.\deploy.ps1                  # 不带参数 = 全量重建（等同 -All）
.\deploy.ps1 -Service web     # 只重建前端
.\deploy.ps1 -Service api     # 只重建后端
.\deploy.ps1 -All             # 三个服务逐个重建
.\deploy.ps1 -UploadOnly      # 只传代码不构建，用来检查服务器状态
```

## 出问题怎么办

### 部署失败，站点打不开

看日志：

```powershell
ssh -i "$env:USERPROFILE\.ssh\_yuxiao.pem" root@47.111.71.156 `
  "cd /root/teamblog/ops/compose && docker compose -f compose.prod.yaml --env-file .env.prod logs --tail=80"
```

### 改了代码反而不对，想回滚

```powershell
# 本地回退到上一个提交
cd D:\TeamBlog
git log --oneline -5
git revert <提交号>
# 或直接
git checkout HEAD~1 -- teamblog/web

# 重新部署
cd teamblog\ops
.\deploy.ps1 -Service web
```

**数据库迁移不能靠 revert 回退**。已经执行的 V4 不会因为代码回退而撤销。所以迁移要写成「可兼容旧代码」的形式（加字段而不是改字段）。

### 服务器磁盘满了

```powershell
ssh -i "$env:USERPROFILE\.ssh\_yuxiao.pem" root@47.111.71.156 "docker system df && docker builder prune -f --filter until=168h"
```

构建缓存最容易堆积，40G 盘上跑几次构建就可能占掉几个 G。

## 什么情况下需要停机

| 改动 | 需要停机吗 |
|---|---|
| 前端代码 | 不需要，滚动重启 |
| 后端代码 | 不需要，但重启期间 3–5 秒不可用 |
| 数据库加字段 | 不需要 |
| 改数据库字段类型 | **需要**，先停 api 再迁移 |
| 改 `.env.prod` | 需要重启对应服务 |
| 换证书 | 只需 reload nginx |

## 别忘了

**每次改完 commit 一次。**

```powershell
cd D:\TeamBlog
git add -A
git commit -m "feat(web): 改了什么"
```

服务器上跑的是你本地的代码，但**本地代码如果没有提交，回滚就没依据**。出问题时只能靠 git 那一次提交救你。

推送 GitHub 经常失败（国内网络），但**本地提交本身就够用了**，不需要远程仓库也能回滚。
