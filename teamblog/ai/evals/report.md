## G1 · general_concept · PASS

**问**：Spring Boot 3 是什么？

**答**（首字节 1.65s）：

```
Spring Boot 3 是 Java 生态里一个主流的后端开发框架，用来快速构建可独立运行的、生产级的 Spring 应用。

简单说，它帮你把 Spring 全家桶的配置、依赖、部署都简化了，让你更专注于业务代码。

几个关键点：

- **基于 Spring 6**  
  Spring Boot 3 底层是 Spring Framework 6，要求 Java 17 及以上版本。

- **快速启动**  
  内置 Tomcat、Jetty 等服务器，直接打成 jar 包就能运行，不需要额外部署 war 到外部服务器。

- **自动配置**  
  根据你引入的依赖自动配置组件，比如引入 PostgreSQL 驱动和 JPA，它就会自动帮你配好数据源。

- **依赖管理**  
  通过 starter 统一管理依赖版本，比如 `spring-boot-starter-web`、`spring-boot-starter-data-jpa`。

- **适合微服务**  
  常和 Spring Cloud 配合，做服务注册、配置中心、网关等。

在你们的 TeaLog 项目里，Spring Boot 3 主要负责提供后端 API 服务，配合 PostgreSQL 和 Flyway 完成打卡、积分等业务逻辑。
```

## G2 · general_concept · PASS

**问**：Flyway 是干什么的？

**答**（首字节 1.20s）：

```
Flyway 是数据库迁移（Migration）工具，主要用来**版本化管理数据库表结构**。

在这个项目里，它的作用是：

- 把建表、改表等 SQL 脚本按版本管理起来
- 项目启动时自动执行未执行过的迁移脚本
- 保证不同环境（开发、测试、生产）的数据库结构一致

常见用法是：

```sql
-- V1__init.sql
CREATE TABLE check_in (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    check_date DATE NOT NULL
);
```

文件名里的 `V1` 是版本号，`__` 后面是描述。Flyway 会记录哪些版本已经执行过，下次只跑新增的脚本。

简单说：**它就是数据库版本的 Git + 自动执行器**。
```
