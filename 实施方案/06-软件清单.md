# 开发环境软件清单

> 目标：四个人在 Windows 上装完就能跑批次 0，不多装一个用不上的东西。
> 一句话结论：**Git + JDK 21 + Docker Desktop + Node 22 + (AI 同学加 Python 3.12)**，其余都是可选项。

---

## 1. 总表

| 软件 | 版本 | 用途 | 谁必须装 | 验证命令 |
|---|---|---|---|---|
| Git | 2.40+ | 版本管理 | 全员 | `git --version` |
| JDK（Temurin） | **21 LTS** | 跑 Spring Boot | 后端、测试 | `java -version` |
| Docker Desktop | 4.30+ | PG、打包、联调 | 全员 | `docker compose version` |
| Node.js | **22 LTS** | Next.js 前端 | 前端、（测试跑 e2e） | `node -v` |
| pnpm | 9.x | 前端包管理 | 前端 | `pnpm -v` |
| Python | **3.12** | FastAPI | AI、测试（跑 AI 单测） | `python --version` |
| uv | 0.5+ | Python 依赖与虚拟环境 | AI | `uv --version` |
| IntelliJ IDEA Community | 2024.3+ | Java 开发 | 后端 | — |
| VS Code | 最新 | TS / Python 开发 | 前端、AI | — |
| Playwright（浏览器） | 随项目 | e2e | 测试 | `npx playwright --version` |

**不需要单独装 Maven**：`start.spring.io` 生成的工程自带 `mvnw`，用 `./mvnw` 即可，版本由 wrapper 锁死，四个人的 Maven 版本天然一致。

## 2. Windows 安装（winget 批量）

```powershell
winget install --id Git.Git -e
winget install --id EclipseAdoptium.Temurin.21.JDK -e
winget install --id Docker.DockerDesktop -e
winget install --id OpenJS.NodeJS.LTS -e
winget install --id Microsoft.VisualStudioCode -e
winget install --id JetBrains.IntelliJIDEA.Community -e

# 仅 AI 同学
winget install --id Python.Python.3.12 -e
pipx install uv
```

装完**重开终端**（PATH 才生效），然后：

```powershell
corepack enable        # 启用 pnpm（Node 22 自带 corepack）
corepack prepare pnpm@9.12.0 --activate
```

Docker Desktop 首次启动要点：

- 后端选 **WSL 2**（不是 Hyper-V），Windows 10/11 家庭版也支持；
- 设置里开启 "Use the WSL 2 based engine"；
- 内存不足的机器在 `.wslconfig` 里限一下（见 §6）。

## 3. 版本验证（装完一次跑完）

```powershell
git --version
java -version           # 必须显示 21.x
docker --version
docker compose version  # 必须 v2.x（不是 1.29 的 docker-compose）
node -v                 # v22.x
pnpm -v                 # 9.x
python --version        # 3.12.x（仅 AI）
uv --version
```

四项对不上就不用往下走：JDK 是 17、Node 是 18、compose 是 v1，后面每一步都会以奇怪的方式失败。

## 4. 服务端软件（2C4G Ubuntu 22.04）

| 软件 | 用途 | 备注 |
|---|---|---|
| Docker Engine + compose 插件 | 跑 web/api/ai/db/nginx | `curl -fsSL https://get.docker.com \| sh` |
| Nginx | 反代与 TLS 终止 | 用容器跑，不装宿主 nginx（避免和 1Panel 打架） |
| 1Panel（可选） | 面板、证书、计划任务 | 团队不熟命令行时用；装了就让它管 Nginx 与证书 |
| rclone | 备份到对象存储 | `apt install rclone` |
| cron | 每日 03:10 备份 | 系统自带 |
| psql 客户端 | 应急连库 | `apt install postgresql-client-16` |

**服务器上不装**：JDK、Node、Python、Maven。所有构建在 CI 完成，服务器只 `docker pull`——2C4G 上跑 Maven 构建必 OOM。

---

## 5. 明确不用装的（比装什么更重要）

| 不装 | 原因 |
|---|---|
| **本机 PostgreSQL** | 会和容器抢 5432 端口，踩过一次就要排查半小时。客户端操作用 `docker compose exec db psql -U blog` |
| Maven | 用项目自带 `mvnw`，版本一致 |
| Prisma / SQLite | 已改为 Flyway + Flyway 管迁移，SQLite 会让 `date`/`jsonb`/`CHECK` 语义失真 |
| Redis | 一期限流走内存 + PG 计数，量级没到 |
| Nginx（Windows 版） | 开发期用 Next 的 `rewrites` + compose，不需要本机反代 |
| MinIO / 对象存储 | 一期图片落本地卷，二期再换 |
| Celery / 消息队列 | 只有一个定时任务，`@Scheduled` 够用 |
| Postman 全家桶 | 用 `curl` + `.http` 文件（IDEA/VS Code 原生支持），脚本可进仓库 |

## 6. 机器配置与 WSL 限制

| 项 | 建议 | 说明 |
|---|---|---|
| 内存 | **16GB 起** | Docker + IDEA + Node + PG 同开约 8–10GB；8GB 机器会频繁换页 |
| 磁盘 | 30GB 空闲 | 镜像、node_modules、Maven 仓库各占几个 GB |
| CPU | 4 核 | 2 核机器编译 Next 会明显卡 |

16GB 机器建议在 `C:\Users\<你>\.wslconfig` 限制 WSL 占用，否则 Docker 会把内存吃满：

```ini
[wsl2]
memory=6GB
processors=4
swap=2GB
```

改完 `wsl --shutdown` 生效。

## 7. 国内网络（可选但省时间）

```bash
# npm
pnpm config set registry https://registry.npmmirror.com

# Maven：改 ~/.m2/settings.xml 加阿里云镜像
# Docker：Docker Desktop → Settings → Docker Engine 加 registry-mirrors
```

注意：**镜像源只影响下载速度，不影响产物**。CI 里不要配镜像源，避免“本地能构建、CI 报错”这类环境差异。

## 8. 版本锁定（保证四个人环境一致）

| 文件 | 内容 | 作用 |
|---|---|---|
| `api/mvnw` + `.mvn/wrapper/maven-wrapper.properties` | wrapper 版本 | Maven 版本一致 |
| `web/.nvmrc` | `22` | Node 版本一致 |
| `web/package.json` → `packageManager` | `pnpm@9.12.0` | 包管理器版本一致 |
| `ai/pyproject.toml` + `uv.lock` | Python 3.12 + 锁定的依赖 | 依赖一致（**锁文件必须提交**） |
| `api/.sdkmanrc` 或 `pom.xml` 的 `<java.version>21</java.version>` | Java 版本 | 编译目标一致 |
| `.gitattributes` | `* text=auto eol=lf` | 防止 Windows CRLF 把 shell 脚本改坏 |

`.gitattributes` 很容易被忽略，但它决定的是一年后 `backup.sh` 还能不能在 Linux 上跑。

## 9. 首次自检清单

新同学加入时按顺序确认，全绿才算环境就绪：

1. `git clone` 仓库，`cd teamblog` 能看到 `web/ api/ ai/ ops/`
2. `docker compose -f ops/docker-compose.dev.yml up -d` → `ps` 显示 healthy
3. `psql "postgresql://blog:blog_dev_pw@localhost:5432/blog" -c "\dt"` 有 11 张表
4. `cd api && ./mvnw -q spring-boot:run` 能启动
5. `curl localhost:8080/api/v1/health` 返回 `"db":"UP"`
6. `cd web && pnpm i && pnpm dev` 打开 3000 端口
7. （AI 同学）`cd ai && uv sync && uv run uvicorn app.main:app --reload` 打开 8000 端口

任何一步失败，先看 [05-批次0-执行步骤.md](./05-批次0-执行步骤.md) 末尾的「常见失败」表，再问人。
