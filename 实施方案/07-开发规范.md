# TeamBlog 开发规范

> 这份文档约束**怎么写**，不约束**写什么**（见 03 实施方案）与**先写哪个**（见 04 实施顺序）。
>
> 每条规则有编号（`J-03`、`A-07`），评审时直接引用编号，不吵"我觉得该这样"。
>
> 判定标准只有一条：**规则是否能被工具或测试自动检查**。不能自动检查的，写进评审清单，靠人。

---

## 0. 总则

| 编号 | 规则 |
|---|---|
| G-01 | 三服务各自独立可运行、独立部署、独立回滚；不允许 web 直接连数据库，不允许 ai 写业务表 |
| G-02 | 业务规则只存在于一个地方：api 的 service 层。前端不做规则，AI 服务不做规则 |
| G-03 | 任何"临时方案"必须带 `// TODO(owner, 日期): 原因` 与对应 issue 编号，否则不接受 |
| G-04 | 遇到规范没覆盖的情况，先按最接近的规则做，并在 PR 里提出补充规范，而不是各写各的 |
| G-05 | 规范冲突时的优先级：安全 > 正确性 > 可读性 > 一致性 > 个人偏好 |
| G-06 | 中文注释写"为什么"，代码写"做什么"；不写"// 设置 name"这种复述 |

## 1. 仓库、分支与提交

### 1.1 分支模型

采用 **trunk-based**：`main` 永远可部署，功能分支存活不超过 2 天。

| 编号 | 规则 |
|---|---|
| R-01 | 分支命名：`feat/<scope>-<简短描述>`、`fix/`、`chore/`、`docs/`，例如 `feat/api-checkin-streak` |
| R-02 | 从 `main` 切出，合并回 `main`，不设 `develop`（4 人团队多一条长期分支只会增加合并成本） |
| R-03 | 分支超过 2 天没合，必须拆小或同步 `main`；超过 5 天的分支视为设计问题，回到评审 |
| R-04 | 合并用 **squash**，一个 PR 一个提交，历史线性可读 |
| R-05 | `main` 开启保护：CI 全绿 + 至少 1 人 approve，禁止直接 push |

### 1.2 提交信息（Conventional Commits）

```
<type>(<scope>): <subject>

[body: 为什么这么改，不是怎么改]

[footer: BREAKING CHANGE / Refs #123]
```

| 编号 | 规则 |
|---|---|
| R-06 | `type` 只能是 `feat / fix / refactor / perf / test / docs / chore / build / ci` |
| R-07 | `scope` 只能是 `web / api / ai / db / ops / docs`，跨服务时用最大的那个或拆提交 |
| R-08 | subject 用中文或英文均可，但**同一仓库不混用**（当前定：中文），不超过 50 字，句末不加句号 |
| R-09 | body 写动机与取舍，不写"修改了 XxxService 的 if 判断"——diff 里已经有了 |
| R-10 | 破坏性变更（改接口字段、改迁移）必须 `!` 标记并在 footer 写迁移说明 |

示例：

```
feat(api): 打卡支持连续天数与账本发放

原先 total_points 直接累加，重复请求会重复加分。改为 point_events 唯一键
兜底 + 同事务 increment，并为 7/14/30 天奖励按连续段起始日去重。

Refs #42
```

### 1.3 PR

| 编号 | 规则 |
|---|---|
| R-11 | 一个 PR 只做一件事；改动 **≤ 400 行**（含测试），超过就拆 |
| R-12 | PR 标题与提交信息同格式；描述里写「改了什么 / 为什么 / 怎么验」三行 |
| R-13 | 作者先自查一遍 diff，再 @ 评审人；不允许"先开着等别人找问题" |
| R-14 | 评审 SLA：24 小时内给出第一次反馈；超过 48 小时无人看，直接找对方口头同步 |
| R-15 | 评审意见用 `nit:` 前缀区分"必须改"与"建议"；`nit` 不阻塞合并 |

PR 模板：

```markdown
## 改了什么
## 为什么
## 怎么验证
- [ ] 单测 / 集成测试覆盖
- [ ] 本地跑通（贴命令与输出）
- [ ] 涉及权限的接口，权限矩阵用例已加
- [ ] 涉及表结构，只有 Flyway 迁移，无手工改库
- [ ] 涉及接口字段，前端类型已重新生成
```

## 2. Java 规范（api）

### 2.1 分层与包结构

```
com.teamblog
├─ auth/          SecurityConfig, JwtService, JwtFilter, RefreshTokenService, AuthController
├─ user/          User, UserRepository, UserService, UserController, dto/
├─ project/       Project, ProjectRepository, ProjectService, ProjectController, dto/
├─ learning/ checkin/ points/ comment/ feedback/ admin/
└─ common/        ApiResponse, ErrorCode, BusinessException, GlobalExceptionHandler,
                  RequestIdFilter, ClockConfig, RateLimiter
```

| 编号 | 规则 |
|---|---|
| J-01 | **按业务分包**，不按技术分层分包（没有 `controllers/` `services/` 大平层） |
| J-02 | 一个包内：`Controller` 只做 DTO 转换与校验，`Service` 放全部业务与事务，`Repository` 只做查询 |
| J-03 | Entity **不出 service 层**；Controller 只接触 `record` DTO |
| J-04 | DTO 用 `record`，命名 `XxxRequest / XxxResponse`，放在 `dto` 子包 |
| J-05 | 不允许 Controller 里写 `if` 业务分支；发现即 review 打回 |

### 2.2 依赖注入与配置

| 编号 | 规则 |
|---|---|
| J-06 | 构造器注入，用 `@RequiredArgsConstructor`；**禁止 `@Autowired` 字段注入** |
| J-07 | 配置项一律 `@ConfigurationProperties` + `@Validated`，不散落 `@Value` |
| J-08 | 需要"当前用户"时从 `@AuthenticationPrincipal` 或 `SecurityContextHolder` 取，不从请求参数取 |

### 2.3 事务与并发

| 编号 | 规则 |
|---|---|
| J-09 | `@Transactional` 只加在 **public 的 service 方法**上；不加 Controller、不加 private 方法 |
| J-10 | 事务内**禁止**调外部 HTTP（AI 服务、GitHub），会长时间持锁 |
| J-11 | 计数类字段用 `UPDATE ... SET x = x + ?`（JPQL `@Modifying`）或数据库原子操作，**禁止先读后写** |
| J-12 | 打卡 + 发积分必须在**同一个事务**里完成；中途失败整体回滚 |

### 2.4 时间

| 编号 | 规则 |
|---|---|
| J-13 | 注入 `Clock` Bean，**禁止直接 `LocalDate.now()` / `Instant.now()`**（否则没法测跨天） |
| J-14 | 业务日期用 `LocalDate` + `ZoneId.of("Asia/Shanghai")`；时间戳列映射 `OffsetDateTime` |
| J-15 | 打卡日期只能由 `DateProvider.today()` 产出，不允许从客户端传入 |

### 2.5 异常与返回

| 编号 | 规则 |
|---|---|
| J-16 | 业务失败抛 `BusinessException(ErrorCode)`，由 `@RestControllerAdvice` 统一转信封；**不 catch 后返回 null** |
| J-17 | 不使用 `RuntimeException("...")` 裸抛；新增错误码必须同步到 §5.3 的表 |
| J-18 | 不吞异常：`catch (Exception e) { }` 一律 review 打回 |

```java
public class BusinessException extends RuntimeException {
    private final ErrorCode code;
    public BusinessException(ErrorCode code, Object... args) {
        super(code.format(args));
        this.code = code;
    }
}
```

### 2.6 校验

| 编号 | 规则 |
|---|---|
| J-19 | 入参用 Jakarta Validation（`@NotBlank @Size @Pattern @Min`），Controller 加 `@Valid` |
| J-20 | **数据库 CHECK 与 Bean Validation 双写**：前者兜底，后者给用户可读信息 |
| J-21 | 跨字段规则（如"证书必须有图或链接"）写在 service，不写在注解里 |

### 2.7 Lombok

| 编号 | 规则 |
|---|---|
| J-22 | Entity 只用 `@Getter`、`@Setter`（必要时）；**禁止 `@Data` 加在 Entity 上**（equals/hashCode 会踩代理） |
| J-23 | 禁止 `@Builder` 加在 Entity 上，用静态工厂或构造器 |
| J-24 | DTO 用 `record`，不需要 Lombok |

## 3. TypeScript / Next.js 规范（web）

### 3.1 组件与数据获取

| 编号 | 规则 |
|---|---|
| T-01 | 默认 **Server Component**；只有需要状态、事件、浏览器 API 才加 `"use client"`，且加在叶子组件上 |
| T-02 | 首屏数据在 RSC 里取，**禁止在 `useEffect` 里拉首屏数据**（会多一次空白期） |
| T-03 | 服务端 fetch 必须 `cache: 'no-store'`，并透传 `Cookie`；漏了这一个参数，就可能把 A 的页面缓存给 B |
| T-04 | Next 15 的 `params`、`cookies()`、`headers()` 都是 **async**，必须 `await` |
| T-05 | 不引全局状态库；当前用户用 Context，其他数据靠 RSC + `router.refresh()` |

```tsx
// 正确：Next 15 的 params 是 Promise
export default async function Page({ params }: { params: Promise<{ username: string }> }) {
  const { username } = await params;
  const u = await api.getUser(username);
  return <Profile user={u} />;
}
```

### 3.2 类型与接口

| 编号 | 规则 |
|---|---|
| T-06 | 接口类型**只能**来自 `openapi-typescript` 生成文件；手写 `interface` 描述接口字段视为不合格 |
| T-07 | 禁止 `any`（ESLint `no-explicit-any: error`）；实在不确定用 `unknown` + 收窄 |
| T-08 | 所有 fetch 走统一的 `apiClient`，不允许散落 `fetch(` 调用（便于统一错误处理与 baseURL） |
| T-09 | 接口错误按 `error.code` 分支，展示文案从 `messages.ts` 取，**不直接渲染后端 message** |

### 3.3 目录与命名

| 编号 | 规则 |
|---|---|
| T-10 | 路由目录 `kebab-case`；组件文件 `PascalCase.tsx`；工具函数 `camelCase.ts` |
| T-11 | 组件超过 150 行就拆；一个文件只导出一个主组件 |
| T-12 | `lib/` 放无 UI 逻辑（请求、格式化、校验），`components/` 只放 UI |
| T-13 | 颜色、间距、圆角一律走 Tailwind token；禁止裸 `style={{}}` |

### 3.4 状态与交互

| 编号 | 规则 |
|---|---|
| T-14 | 每个路由段必须有 `loading.tsx` 与 `error.tsx`；列表必须有空态文案 |
| T-15 | 提交类按钮必须 disabled + loading，防止重复提交（后端幂等是兜底，不是替代） |
| T-16 | 表单校验用 `lib/validators` 的 zod schema，**与后端 Bean Validation 一一对应** |
| T-17 | 外链统一 `rel="noopener noreferrer"` + `target="_blank"` |

### 3.5 安全

| 编号 | 规则 |
|---|---|
| T-18 | Markdown 渲染必须过 `rehype-sanitize`；禁止 `dangerouslySetInnerHTML`（除 AI 流式文本，且不解析 HTML） |
| T-19 | 不在客户端存储 token；凭证只在 httpOnly Cookie 里 |
| T-20 | 图片 `next/image` 或显式宽高，禁止布局抖动 |

## 4. Python 规范（ai）

### 4.1 结构与异步

| 编号 | 规则 |
|---|---|
| P-01 | `routers/` 只做参数校验与响应拼装；业务在 `services/`；prompt 放 `prompts.py` |
| P-02 | 全链路 async；调用模型用 `AsyncOpenAI`，HTTP 用 `httpx.AsyncClient` |
| P-03 | **禁止在 async 函数里做阻塞调用**（`requests`、`time.sleep`、同步文件读大文件） |
| P-04 | 每个外部调用设超时（连接 5s / 读 30s），不设超时的调用视为 bug |
| P-05 | 依赖用 `uv` 管理，`uv.lock` 必须提交 |

### 4.2 类型与配置

| 编号 | 规则 |
|---|---|
| P-06 | 所有函数有类型注解；`ruff` + `pyright`（basic 模式）在 CI 跑 |
| P-07 | 配置用 `pydantic-settings`（`Settings` 类），不直接 `os.getenv` |
| P-08 | 请求/响应用 pydantic v2 model，不用裸 dict |

### 4.3 流式与资源

| 编号 | 规则 |
|---|---|
| P-09 | SSE 生成器必须 `try/finally` 关闭上游连接与释放限流计数 |
| P-10 | 每轮检查 `await request.is_disconnected()`，用户关页面立即停止（这是成本控制，不是优化） |
| P-11 | 事件格式只能是 `delta / done / error` 三种，改动需同步前端与契约 |
| P-12 | 错误也要发 SSE `event: error`，因为响应头已经 200，不能改状态码 |

### 4.4 日志与隐私

| 编号 | 规则 |
|---|---|
| P-13 | 不打印 prompt 全文与用户问题全文（只打长度与摘要哈希），避免日志泄漏 |
| P-14 | IP 一律存哈希（`sha256(ip + SALT)`），不存明文 |

## 5. 接口规范

### 5.1 URL 与返回

| 编号 | 规则 |
|---|---|
| A-01 | 资源复数名词：`/api/v1/projects`、`/api/v1/learning-logs`；动作型端点用动词子路径（`/checkins`、`/ai/project-chat`） |
| A-02 | 版本前缀 `/api/v1`；不兼容变更升 `/api/v2`，不做同路径改语义 |
| A-03 | 成功 `{"ok":true,"data":...}`；失败 `{"ok":false,"error":{"code","message"}}`；**三服务同一格式** |
| A-04 | JSON 字段 `camelCase`，数据库 `snake_case`；映射只在一处（DTO） |
| A-05 | 时间用 ISO 8601 带时区（`2026-10-23T21:30:00+08:00`），日期用 `2026-10-23` |
| A-06 | ID 一律字符串（UUID），前端不比较大小、不做数值运算 |

### 5.2 状态码与分页

| 编号 | 规则 |
|---|---|
| A-07 | 200 成功 / 201 创建 / 204 无内容（删除） / 400 参数格式 / 401 未登录 / 403 无权限 / 404 不存在 / 409 冲突 / 422 语义违反 / 429 限流 / 503 不可用 |
| A-08 | 分页统一 cursor：请求 `?cursor=&limit=`（默认 20，上限 100），响应 `{items, nextCursor}` |
| A-09 | 列表接口必须显式声明排序（默认 `createdAt desc`），不依赖数据库默认顺序 |
| A-10 | 写接口不接受客户端传来的计分字段、角色字段、时间字段——全部由服务端决定 |

### 5.3 错误码表（唯一真相）

| code | HTTP | 含义 |
|---|---|---|
| `UNAUTHENTICATED` | 401 | 未登录 / token 无效 |
| `SESSION_REVOKED` | 401 | tokenVersion 失效（改密码、改角色、被移除） |
| `FORBIDDEN` | 403 | 角色或归属不满足 |
| `NOT_FOUND` | 404 | 资源不存在或已下架 |
| `VALIDATION_FAILED` | 400 | 参数格式错误 |
| `RULE_VIOLATED` | 422 | 语义违反（如回复的回复、类型必填缺失） |
| `CONFLICT` | 409 | 唯一键冲突（如重复打卡） |
| `RATE_LIMITED` | 429 | 触发限流 |
| `UPSTREAM_FAILED` | 503 | AI 上游不可用 |
| `INTERNAL` | 500 | 未预期错误（不暴露堆栈） |

新增错误码：先改这张表 → 再改 `ErrorCode` 枚举 → 再改前端文案，三步缺一不可。

### 5.4 幂等与限流

| 编号 | 规则 |
|---|---|
| A-11 | 打卡靠数据库唯一键，重复请求返回 409，不能返回 500 |
| A-12 | 上传与创建类接口超时重试必须安全：先查后写或依赖唯一键 |
| A-13 | 限流响应必须带 `Retry-After` 头 |

## 6. 数据库规范

### 6.1 迁移

| 编号 | 规则 |
|---|---|
| D-01 | 命名 `V{n}__{snake_case}.sql`；一次迁移只做一件事（建表 / 加列 / 加索引分开） |
| D-02 | **已执行过的迁移永不修改**（含注释）；改错就加新迁移 |
| D-03 | 迁移里**不写业务数据**；种子放 `db/seed/`，只在 dev profile 加载 |
| D-04 | 只有 api 服务跑 Flyway；ai 服务启动不做任何 DDL |
| D-05 | 破坏性变更（删列/改类型）必须分两次发布：先兼容（加新列 + 双写），再清理 |
| D-06 | 大表加索引用 `CREATE INDEX CONCURRENTLY` 并单独一个迁移（不在事务里） |

### 6.2 表设计

| 编号 | 规则 |
|---|---|
| D-07 | 表名复数 `snake_case`；主键 `id uuid`；外键 `{表名单数}_id` |
| D-08 | 时间戳一律 `timestamptz`；业务日期用 `date`；**禁止 `timestamp without time zone`** |
| D-09 | 每张表必有 `created_at default now()`；可变表加 `updated_at` + 触发器兜底 |
| D-10 | 枚举用 `varchar + CHECK`（不用 PG enum 类型，避免 Hibernate 与迁移互相打架） |
| D-11 | 每个外键列必须建索引（PG 不会自动建，删父行时会全表扫） |
| D-12 | 命名前缀：索引 `ix_`、唯一 `uq_`、约束 `ck_`；一个迁移内的命名全局唯一 |
| D-13 | 软删用 `deleted_at timestamptz` / `removed_at`；**所有查询必须显式过滤**，Repository 层默认方法不带已删数据 |

### 6.3 查询

| 编号 | 规则 |
|---|---|
| D-14 | 禁止 N+1：关联列表用 `join fetch` 或一次 `IN` 查询，热力图/统计用 `groupBy` 或原生 SQL |
| D-15 | 原生 SQL 必须参数化（`?` 或 `:name`），**禁止字符串拼接** |
| D-16 | 事务内不做分页大查询；导出类需求单独通道 |
| D-17 | 慢查询阈值 500ms，超过就加索引或改写，不看"数据量还小" |

## 7. 安全编码

| 编号 | 规则 |
|---|---|
| S-01 | 每个写接口三重校验：登录态 → 角色 → **资源归属**。URL 级规则只是第一道 |
| S-02 | 角色以数据库 `users.role` 为准；token 里的 role 只用于展示与日志 |
| S-03 | 密码用 BCrypt(12)；禁止 MD5/SHA 直接存密码；禁止日志打印密码或 token |
| S-04 | refresh token 只存 SHA-256 哈希；明文只在 Cookie 里存在一次 |
| S-05 | 上传文件：校验 magic bytes、扩展名白名单、大小上限、随机重命名、禁 SVG |
| S-06 | 用户内容只存 Markdown 源文，不存 HTML；渲染时清洗 |
| S-07 | Secret 只从环境变量读；`.env` 永不提交；`JWT_SECRET` 轮换会导致全员掉线，需提前通知 |
| S-08 | 数据库账号最小权限：`ai_reader` 只能 SELECT 视图 + 写 `ai_conversations` |
| S-09 | 对外错误信息不暴露堆栈、SQL、内部路径 |
| S-10 | IP 只存哈希；邮箱是否公开必须走 `email_public` 开关，且接口层过滤 |

## 8. 日志与可观测

| 编号 | 规则 |
|---|---|
| L-01 | 结构化 JSON：`ts, level, service, requestId, userId?, msg, ...fields` |
| L-02 | `requestId` 由 Nginx 生成（`X-Request-Id`），三服务透传，跨服务排查靠它 |
| L-03 | 级别：ERROR 需人处理；WARN 异常但已降级；INFO 业务节点（登录、打卡、发布）；DEBUG 仅本地 |
| L-04 | 记录业务事件而非每行代码：登录失败、403、积分发放、AI 限流、对账差异 |
| L-05 | 禁止日志中出现：密码、token、完整邮箱、完整 IP、prompt 全文 |
| L-06 | 关键路径打点：AI 首字节延迟（TTFT）、DB 查询耗时、外部调用耗时 |

## 9. 测试规范

| 编号 | 规则 |
|---|---|
| Q-01 | 命名：`方法_场景_期望`，中文或英文均可，同文件不混用 |
| Q-02 | 测试分层：service 单测（纯逻辑）→ 集成测试（`@SpringBootTest` + Testcontainers）→ e2e（Playwright） |
| Q-03 | **禁止用 H2 替代 PG** 跑集成测试；`date`、`jsonb`、唯一冲突语义都不一致 |
| Q-04 | 时间相关测试用注入的 `Clock`，不用 `Thread.sleep`、不依赖"今天" |
| Q-05 | 每个权限敏感接口必须有「成员 token 打管理员接口 = 403」用例 |
| Q-06 | 积分/等级/连续段：v1.1 §4.5 的 11 条用例是**最低集合**，一条不能少 |
| Q-07 | 覆盖率只考核 service 层，目标 70%；不为凑覆盖率给 getter 写测试 |
| Q-08 | 测试数据用工厂方法（`aUser().member()`），不复制粘贴 JSON |
| Q-09 | 测试必须能重复跑：不依赖执行顺序、不依赖库里已有数据 |

## 10. CI / CD

| 编号 | 规则 |
|---|---|
| C-01 | PR 流水线：lint → 单测 → 集成测试（Testcontainers）→ 契约 diff → 前端类型检查 → 构建镜像 |
| C-02 | **契约 diff 失败必须修**：后端改了字段却没重新生成前端类型，CI 红 |
| C-03 | 镜像 tag 用 `sha-<短commit>`，不用 `latest`；部署按 tag 回滚 |
| C-04 | 服务器不构建镜像；只 `docker compose pull && up -d` |
| C-05 | 发布窗口：工作日 10:00–17:00；周五下午与节前不发版 |
| C-06 | 回滚策略：镜像回退一版；数据库**只前进**，回滚数据库 = 还原备份（所以备份必须先演练） |
| C-07 | 每次发布记录：版本号、变更摘要、执行人、验证结果（上不上线与这条记录挂钩） |

## 13. 规范的强制执行

规则不落到工具上就只是建议。最低配置：

| 栈 | 工具 | 卡什么 |
|---|---|---|
| Java | Spotless + google-java-format | 格式 |
| Java | ArchUnit 测试 | 分层依赖方向、禁止 Controller 依赖 Repository |
| Java | 编译参数 `-Xlint:all -Werror` | 警告即错误 |
| TS | ESLint（`no-explicit-any`、`no-floating-promises`）+ Prettier | 类型与异步 |
| TS | `tsc --noEmit` | 类型 |
| Python | `ruff format` + `ruff check` + `pyright` | 格式、lint、类型 |
| SQL | Flyway 命名检查 + `squawk` | 迁移规范、加锁风险 |
| 提交 | commitlint（可选） | 提交格式 |

ArchUnit 里最值得写的两条：

```java
@ArchTest
static final ArchRule controllers_must_not_touch_repositories =
    noClasses().that().haveSimpleNameEndingWith("Controller")
        .should().dependOnClassesThat().haveSimpleNameEndingWith("Repository");

@ArchTest
static final ArchRule only_points_service_updates_points =
    noClasses().that().haveSimpleNameNotEndingWith("PointsService")
        .should().callMethodWhere(target -> target.getName().equals("addPoints"));
```

## 14. 禁止清单（出现即打回）

| # | 禁止 | 原因 |
|---|---|---|
| 1 | 前端隐藏按钮当权限控制 | 抓包即可越权 |
| 2 | `ddl-auto=update/create` | 生产少一列，排查半天 |
| 3 | 手改生产数据库 | 与迁移不一致，下次迁移失败 |
| 4 | 在 Controller 写业务 if | 规则分散，测试写不了 |
| 5 | 事务里调 HTTP | 长事务、连接池打满 |
| 6 | `LocalDate.now()` 直接调用 | 跨天用例无法测试 |
| 7 | 明文日志打 token / 密码 / 完整 IP | 泄露即事故 |
| 8 | `catch (Exception e) {}` | 吞异常，问题延后爆发 |
| 9 | 拼 SQL 字符串 | 注入 |
| 10 | 提交 `.env` / 密钥 | 永久留在 git 历史里 |
| 11 | 用 `latest` tag 部署 | 无法回滚到确定版本 |
| 12 | 修改已上线的 Flyway 迁移 | 环境间校验和不一致，启动失败 |
| 13 | 依赖里加"备用"框架（Redis/ORM 混用） | 团队 4 个人，认知负担是硬成本 |
| 14 | 在 `main` 直接提交 | 破坏可部署性 |
